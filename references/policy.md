# 判定与处置策略

## 五个结论，五种动作

| verdict | 含义 | agent 该做什么 |
| --- | --- | --- |
| clean | 两边都没有不良记录 | 继续，但 clean 不等于安全，只是现在没证据 |
| suspicious | 少量引擎命中，或本地有可疑信号 | 可以读、可以静态分析，**不要执行**，不要移动到 PATH |
| malicious | 本地命中，或多引擎命中 | 停手，原样保留文件，把证据交给用户 |
| unknown | VT 没有记录，本地干净 | 当可疑处理：不执行，先问 |
| error | 某个引擎没跑成 | 不能当 clean，说明哪一半缺了 |

## 上传的边界

默认只查哈希。文件内容上传到第三方等于把它交出去，以下情况一律先问：

- 含个人数据（简历、聊天记录、截图）
- 含凭据或配置（`.env`、`config.json`、密钥库）
- 内部代码或未公开的项目产物

只有公开的、可再分发的、明确不敏感的文件才适合 `-Upload`。

## 误报

单个引擎报毒是常态。判定阈值放宽到 3 个引擎，或者本地 Kaspersky 明确给出家族名。碰到 1-2 个引擎命中且本地干净的情况，报 suspicious，把引擎名和家族名都列出来，让用户自己判断。

## 记录

每次扫描把 `path`、`sha256`、`verdict`、两端计数写进一行日志。同一个哈希第二次出现时直接复用上次结论，配额和 CPU 都省。
